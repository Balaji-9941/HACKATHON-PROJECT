1. EXECUTIVE SUMMARY & CORE MISSION
====================================================================================================
PayTelemetry (also referred to as FraudShield AI) is an enterprise-grade, in-flight payment fraud
intelligence platform built specifically for modern real-time payment networks (UPI, IMPS, FedNow,
and instant card rails).

THE CORE PROBLEM IT SOLVES:
Real-time payments settle irreversibly in under 2 seconds. Legacy fraud detection systems present a
fatal dilemma:
- Heavy ML models are too slow to run synchronously in the payment path and run asynchronously
  (15–60 seconds post-settlement)—detecting fraud only after funds have already left the banking ecosystem.
- Rigid legacy rule engines run fast (<10ms) but rely on inflexible thresholds, creating a massive
  70%+ false alarm rate that aggressively blocks legitimate high-value customers. E-commerce merchants
  lose up to 58× more revenue to false declines than to actual fraud!

THE CHRONOFORGE SOLUTION:
PayTelemetry bridges this gap by introducing a multi-tier in-flight telemetry architecture:
1. Sub-20ms Synchronous Hot-Path Scoring: Evaluates 10 continuous telemetry dimensions before account
   balance deduction.
2. 5-Stage Graduated Dynamic Friction: Replaces crude binary "Block vs Allow" logic with adaptive
   interventions (from zero-friction frictionless pass to In-App Confirmation and Biometric Step-Up).
3. In-Flight TreeSHAP Explainability: Decomposes black-box ML predictions into exact mathematical
   feature attributions in real time, generating instant plain-text explanations for both consumers
   and SOC analysts.
4. Active Entity Graph Intelligence: Uncovers multi-hop mule accounts and coordinated layering rings.
5. Non-Blocking Circuit Breakers: Guarantees 99.999% payment availability even if the ML service is offline.

HOT-PATH TRANSACTION EXECUTION SEQUENCE:
1. User enters amount in Consumer UPI UI (e.g. Aarav Patel sending ₹10,00,000 to Sneha Kapoor).
2. Debounced pre-check sensor calls POST /api/transactions/pre-check.
3. Express Gateway fetches customer telemetry baseline (avgTransaction: ₹650, usualLocation, knownDevices).
4. Gateway extracts 10-dimensional normalized feature vector in <3ms.
5. Gateway queries Python ML Service (POST http://127.0.0.1:8000/predict).
   - If ML service responds in <20ms: ML probability (e.g. 0.80) is returned.
   - If ML service is offline/slow: Gateway fallback predicts calibrated score synchronously.
6. Gateway maps risk score (80/100) to Graduated Friction Tier -> "STEPUP" (Biometric Challenge Required).
7. Consumer UI receives response and renders the Biometric Step-Up Modal (FaceID / Fingerprint).
8. Customer authenticates biometrically and taps "Confirm & Pay".
9. Gateway executes POST /api/transactions/confirm, settles transaction, debits balance, and broadcasts
   the event via Socket.io to the Investigator Command Center.

4. MACHINE LEARNING ENGINE & MATHEMATICAL FOUNDATIONS
====================================================================================================
DATASET SPECIFICATIONS:
- Filename: fraudshield_dataset_v2_scored.csv
- Total Records: 112,607 transaction rows
- Fraud Vectors: 15,301 confirmed fraud events (13.6% fraud prevalence)
- Train Set: 90,085 rows (80%) | Held-Out Test Set: 22,522 rows (20%)

THE RAW DATASET BIAS DIAGNOSIS & HOW WE FIXED IT:
In raw financial fraud datasets, 96.5% of positive fraud records have `isFullAccountDrain == True`.
When a standard decision tree or naive XGBoost model is trained on this data:
- The tree learns to split almost exclusively on `isFullAccountDrain`.
- If a customer with a high balance (e.g., ₹25,00,000) makes an extreme transaction (e.g., ₹10,00,000,
  which is 1538× their ₹650 baseline), `isFullAccountDrain` is False (10L < 25L).
- A naive tree model outputs a near-zero probability (0.01 or 1/100), completely missing the 1538× anomaly!

THE CHRONOFORGE BALANCED XGBOOST ARCHITECTURE (balanced-xgboost-v4):
To solve this, we refactored `ml-service/train.py` with multi-vector regularization and data augmentation:
1. Sub-Feature Bagging:
   - `colsample_bytree = 0.65` (Each tree only sees 65% of features, forcing trees to split on amount
     ratios, velocity, hardware novelty, and location variance).
   - `colsample_bylevel = 0.65` (Each depth level forces alternative splits).
2. L1 & L2 Regularization:
   - `reg_alpha = 0.1` (L1 sparsity penalty to prune redundant leaf splits).
   - `reg_lambda = 1.0` (L2 ridge penalty to smooth leaf weights).
3. Multi-Anomaly Augmentation:
   - Synthetically augmented non-drain multi-anomaly vectors (velocity bursts, 10x–1500x amount ratios,
     novel hardware takeovers, off-hour transactions).

THE 10-DIMENSIONAL FEATURE VECTOR:
Every transaction is mathematically encoded into a 10-dimensional normalized vector [f_0 ... f_9]:
1. f_0 (amountRatioNorm): min(2.5, ln(1 + Amount / CustomerAvg) / 4.0)
2. f_1 (velocityNorm): min(1.0, RecentTxnsIn120s / 4.0)
3. f_2 (deviceNovelNorm): 1.0 if deviceId not in customer.knownDevices else 0.0
4. f_3 (locationVarNorm): 1.0 if location differs from customer.usualLocation else 0.0
5. f_4 (temporalNorm): 1.0 if transaction hour outside customer.typicalHours else 0.0
6. f_5 (merchantRiskNorm): 1.0 (Crypto/Gambling), 0.8 (Loan/Wire), 0.6 (Financial), 0.0 (Dining/P2P)
7. f_6 (networkRiskNorm): 1.0 if customer.networkRiskTier > 2 else 0.0
8. f_7 (accountDrainNorm): 1.0 if Amount >= balance * 0.75 and Amount > 10,000 else 0.0
9. f_8 (ruleScoreNorm): Composite multi-signal point score / 100.0
10. f_9 (isHighRiskType): 1.0 for high-risk transfer channels (Wire, Crypto, Loan) else 0.0

5. REAL-TIME EXPLAINABILITY ENGINE (TreeSHAP & NATURAL LANGUAGE)
====================================================================================================
PayTelemetry eliminates the black-box nature of AI fraud detection using exact Shapley values.

MATHEMATICAL FOUNDATION:
Using `shap.TreeExplainer`, the risk score is decomposed into the base expected value plus the sum of
marginal feature contributions:
  Risk Score = phi_0 + SUM(phi_i)

WATERFALL ATTRIBUTION FACTORS:
For every transaction, exact points are assigned to contributing factors:
- Amount Anomaly: Up to +50 points (e.g. "+50 pts — Payment is 1538.5× average baseline")
- Velocity Burst: Up to +30 points (e.g. "+30 pts — Multiple rapid transactions in 120s")
- Device Novelty: Up to +30 points (e.g. "+30 pts — Unrecognized hardware signature")
- Location Variance: Up to +30 points (e.g. "+30 pts — Originated from unregistered geo-location")
- Account Drain: Up to +40 points (e.g. "+40 pts — Outflow represents 95%+ of available balance")

DUAL-AUDIENCE TRANSLATION:
1. Consumer Experience: Human-readable, non-jargon natural language explanation displayed directly
   in the checkout flow.
   Example: "Payment of ₹10,00,000 is 1538.5× your average transaction (₹650)."
2. SOC Investigator Console: Interactive visual waterfall chart (TelemetryDrawer.jsx) showing exact
   mathematical contributions, raw telemetry values, and customer historical baselines.

6. 5-STAGE DYNAMIC GRADUATED FRICTION POLICY
====================================================================================================
Traditional fraud platforms use binary logic: either ALLOW or BLOCK.
PayTelemetry replaces this with a 5-Stage Graduated Friction Model that eliminates false block churn:

+------+-----------+---------------+--------------------+---------------------------------------------------+
| Tier | Score     | Severity      | Friction Level     | User Experience & SOC Action                      |
+------+-----------+---------------+--------------------+---------------------------------------------------+
| 0    | 0 – 30    | none          | none               | Zero friction. Cleared in <15ms (e.g. ₹350 food). |
| 1    | 31 – 50   | low           | banner             | Informational security banner (e.g. late night).  |
| 2    | 51 – 70   | medium        | confirm            | Explicit confirmation review modal.               |
| 3    | 71 – 85   | high          | stepup             | Biometric Step-Up Challenge (FaceID / Fingerprint)|
| 4    | 86 – 100  | critical      | stepup_alert       | Biometric Step-Up + Instant SOC Incident Ticket   |
+------+-----------+---------------+--------------------+---------------------------------------------------+

BENEFIT: A legitimate customer sending ₹10,00,000 to their family is NOT blocked; they simply verify
via Biometrics and complete their transfer smoothly in 2 seconds.
